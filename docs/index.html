Horizon-Next
v2026.1.0 Beta

A 3D game engine, written to be read as much as played.

Horizon-Next is a C++20 engine built on Ogre3D: a reflective actor/component system, engine plugins, DLL-loaded game modules, and Lua scripting — all behind a stable API.

View source code
What the engine covers

Everything you need to run a game, nothing more.

Six core building blocks, each isolated behind a clean interface.

Ogre3D rendering

Cameras, lights and sprites go through an internal rendering interface, ready for Direct3D 11, OpenGL or Vulkan.

Lightweight reflection

Every object exposes its typed properties through a simple macro, with callbacks fired on every change.

Actors & components

Transform, physics and composed — not inherited — components keep every actor simple to read.

Plugins & modules

A game registers its gameplay classes in a separate DLL. The engine itself rarely needs recompiling.

Lua scripting

An embedded Lua VM drives high-level logic without recompiling the engine or the game.

Multiplayer

Player controllers possess actors and each manage their own viewport.

Under the hood

Two namespaces, one clean boundary.

hn:: is the engine — logs, plugins, the Lua VM. hge:: is the game framework exposed to modules: actors, levels, components, input.

Objects & properties

One property, one line

HGE_Object is the base of every reflectable entity. The HPROPERTY macro attaches it to an Observable, checked on every tick.

// player.h class Player : public hge::HGE_Actor { public: int life = 100; Player() { HPROPERTY(life, hge::Exposed); } };
Components

Composed, not inherited

A camera, a light or a collision shape are added to an actor at runtime, via the HCOMPONENT macro.

// in the actor's constructor HCOMPONENT("Sprite", HGE_Sprite); HCOMPONENT("Collider", HGE_ShapeCapsule);
Gameplay modules

The game registers, the engine loads

A module exports its classes into a global factory. HGE_Level::SpawnActor("Player") then instantiates them by name.

// game/src/module.cpp HGE_LINK_MODULE ( HGE_MODULE_REGISTER(Player); )
Engine plugins

Extend the engine, not the game

A plugin implements IPlugin and attaches to the engine itself — the FBX importer is the bundled example. It must be built against the same engine version.

// iplugin.h virtual void Init(EngineInfos*); virtual void Tick(double dt); virtual void StartGame(); virtual void EndGame();

Build from source

On Windows, with CMake. The repo's scripts handle the rest.

  1. git clone https://github.com/oscar-soirey/Horizon-Next.git
    Fetches the repo and its subfolders (engine, example game, FBX plugin).
  2. install_depedencies.bat
    Installs the third-party dependencies needed for the build.
  3. generate.bat
    Generates the CMake project files.
  4. build_and_run.bat
    Builds the engine and the game executable, then runs them. build_and_run_editor.bat does the same for the editor.
